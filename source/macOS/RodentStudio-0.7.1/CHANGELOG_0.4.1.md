# Rodent Desktop Native 0.4.1 — iOS tracking visualization parity

**Basis:** RodentPose iOS 1.0 `DesignSystem.swift`, `Keypoints.swift`, `PoseOverlay.swift`, `ReviewPlayerView.swift`, `PoseInference.swift`; RodentLimb iOS 1.1.2 `DesignSystem.swift`, `PoseTypes.swift`, `SkeletonPainter.swift`, `ReviewPlayer.swift`; RodentFlow iOS 1.3 `TrackingOverlayView.swift`, `AssayVisuals.swift`. These source snapshots are preserved in `OriginalAppSources/`.

## Delivered in this revision

1. **Text size buttons**: A− / A+ in the main toolbar and four presets in Settings. Keyboard shortcuts ⌘+ / ⌘−. The app stores the preference in `rd.fontScale`. Font scaling uses SwiftUI Dynamic Type; hardcoded graphics glyphs, control geometry and some individually-sized text are intentionally not resized.
2. **Original keypoint palette and bone topology**: RodentPose 6 points `red/orange/yellow/green/cyan/purple`, 6 named anatomical links. RodentLimb V2 7 points in exact DLC model order (`lf,lh,rf,rh,tail,nose,mouth`) with original seven hex colors and corresponding limb links. They remain different models and assays.
3. **Review coordinate/time alignment**: `AVAssetImageGenerator` now reports `actualTime`; after decoding, the app searches stored presentation times and uses the corresponding keypoints, **not** the initially requested frame index. If no sufficiently close timestamp match or if orientation/aspect differs, the app **suppresses points and alerts the reviewer**. This is a safety-first response to a previously reported offset. It still requires on-device verification of rotated/mirrored material.
4. **2-second trail restored**: RodentPose anatomical `body_center` (point 4); choice of 1/2/5/10 s. For RodentLimb the displayed tail-base QC trail uses point 4, but this is *not* a new validated RodentLimb event or gait score. No lines across missing observations or large time discontinuities.
5. **Event-aligned review timeline**: tracking QC and available RodentLimb behavior analyzer events occupy distinct lanes. The current frame cursor uses the frame displayed, event click / previous / next seeks, click or drag across the timeline scrubs the video; all are driven by the **saved tracking frame timestamps**. RodentPose original behavior event scoring has not yet been ported, so the timeline cannot show those bouts until generated by the real analyzer.
6. **Long-video review on demand**: when review exceeds the in-memory limit, clicking an event reads only the relevant completed ~2-minute CSV segments, retrieves keypoints and a chosen trail window, and matches them to the displayed video frame PTS. No whole-video array or re-inference is required.
7. **Progress and live preview**: guided batch processing and Advanced → long video both display a downscaled frame with the current skeleton, wall-clock-throttled at approximately 1 Hz, retaining only the latest image; a resume-aware approximate remaining-time estimate uses *this execution's* observed progress instead of assuming 30 FPS. Exact estimate accuracy remains device/video dependent.
8. **Annotation PNG parity**: keypoint screenshot export uses per-model colors and the **actual image timestamp**. If the corresponding stored pose cannot be matched, the screenshot fails explicitly instead of exporting a scientifically misleading overlay. RodentLimb path QC figure now uses tail base rather than left paw; it is not an assay metric.
9. All existing task setup, manually dragged calibrations, magnifiers, model routes, optional exports and long-video checkpoint format v2 are preserved. No model weights bundled.

## Boundaries — not silently changed

- RodentPose's complete `Kinematics` → assay scoring → iOS report visualization pipeline has **not** been ported. Basic trail and QC figures do not substitute for metric/behavior analysis.
- RodentFlow's independent classic centroid algorithm and its results remain unavailable on Desktop until migrated. This revision does not connect a pose model to RodentFlow.
- RodentLimb existing event analyzers remain **not scientifically validated** against human scoring.
- Short-video review and long-video on-demand review differ intentionally in memory strategy and available events.
- No annotated-video export is generated by default; the existing optional movie setting remains disabled.

## Verification before scientific use

- Compile with macOS 14+ Xcode (not available in this development container), then inspect 4 tests: 1. landscape and rotated recordings, 2. high-frame-rate/B-frame video where requested and actual PTS differ, 3. long video past 150,000 frames with event jump, 4. save annotated screenshot and compare to the exact video frame.
- Inspect all 13 point colors and model-specific bone edges against the iOS sample video.
- Compare the 2 s tail and event overlay on representative recordings to the iOS App with the same thresholds, calibration and time selection.
- The real application has **not been built or run on macOS here**. Passing Swift parsing and Xcode-project property-list lint does not establish runtime safety or biological metric parity.
