# 0.5.1 产品逻辑检查与修改记录

检查范围：0.5.0 的引导流程（任务 → 视频与动物 → 校准 → 分析 → 复核与导出）、侧栏切换、批量分析、RodentFlow 面板、复核与导出、科研结果计算与导出。每条写明问题、后果和修改位置。

## A. 文件（视频）切换

| # | 0.5.0 的问题 | 后果 | 0.5.1 的修改 |
|---|---|---|---|
| A1 | 复核页的状态按“文件名 + 帧数”识别（`ReviewExportView.syncRun`） | 两只动物视频同名同长时，切换后仍显示上一只的选择、事件判定、RodentLimb 事件 | 按“工作区视频 ID + 结果文件夹”识别（`runKey`）；RodentLimb 事件计算完成时若已切换则丢弃 |
| A2 | 事件判定和复核备注只在内存里 | 切换视频 / 任务 / 页面 / 语言后丢失 | 保存到视频记录 `VideoRecord.review`（`Core/VideoReview.swift`），属于当前结果文件夹 |
| A3 | 批量分析结束时把“开始时选中的视频”载入共享会话 | 正在复核另一只动物时，复核页可能一直显示“正在读取…” | 不再自动载入；复核页按需载入，并监听会话中的视频变化（`ReviewStepView.load`） |
| A4 | “已载入”只比较视频 ID | 重新分析（新文件夹）后仍显示旧结果 | 会话记录读取的文件夹 `loadedFolder`，`holdsResult(of:)` 同时比较视频和文件夹；重新分析开始时清除该视频已载入的结果 |
| A5 | 读取失败只发一条通知 | 复核页停在“正在读取” | 记录失败原因 `loadFailure`，页面显示原因和“重试” |
| A6 | 快速复核需要整段视频的数据 | 长视频无法快速看前 100 帧 | `QuickReviewLoader` 只读取覆盖所选范围的分段 CSV |

## B. 任务切换与分析队列

| # | 0.5.0 的问题 | 后果 | 0.5.1 的修改 |
|---|---|---|---|
| B1 | RodentFlow 追踪是面板里的 `Task`，不进入会话 | 离开页面后看不到进度，可再次点击启动第二个并发追踪；完成时写入“当前面板显示的视频” | RodentFlow 进入统一队列（`NativeRunSession.enqueue` / `runFlow`），带任务句柄，可暂停（检查点保存）；完成写入它自己的视频 |
| B2 | 队列开始时把所有视频标为“正在分析”，暂停时把没开始的标为“已暂停” | 状态与实际不符 | 视频真正开始时才标记；“全部暂停”只停当前视频，等待中的视频保持原状态；侧栏显示排队位置，可“移出队列” |
| B3 | 有分析在运行时，其他任务的视频显示“在队列中等待” | 实际并不在队列中 | 只有真正在队列中的视频显示排队；否则按钮为“加入队列” |
| B4 | RodentFlow 面板同时出现在“分析”和“复核” | 复核页也能启动追踪，两处状态各自独立 | “分析”只追踪（与 RodentPose / RodentLimb 相同的卡片），“复核”只看结果 |
| B5 | 排队的 RodentFlow 视频使用加入队列时的设置 | 等待期间修改的标定不生效 | 开始追踪时读取该视频当时保存的设置 |
| B6 | RodentFlow 续跑不检查设置 | 暂停后修改场地标定再续跑，会把两种几何混在一个结果里 | 检查点记录设置；几何不同则拒绝续跑并提示“重试”（新文件夹从头分析） |
| B7 | “下一只动物”总是跳到“视频与动物”页 | 复核一批已分析的动物时要来回切页 | 复核页里优先跳到下一只“已分析、尚未复核”的动物并停在复核页 |
| B8 | 任务选择页写着 RodentFlow 追踪器“尚未移植” | 与 0.5.0 实际不符 | 更新说明（任务卡、任务目录、`ASSAY_COVERAGE.json`） |

## C. 设置的唯一来源（与原版一致）

| # | 0.5.0 的问题 | 后果 | 0.5.1 的修改 |
|---|---|---|---|
| C1 | RodentPose 报告用复核页的帧范围覆盖“校准”中的分析起点 / 时长 | 同一只动物的数字随复核范围变化；与 iOS 不同 | 引导流程的结果一律用“校准”中保存的分析时间段（`PoseScienceBridge.report(_:setup:phase:)`，整段轨迹分析 + 时间窗选择，与 iOS 相同）；复核页范围只用于质控图 / 原始导出 / MP4。“高级”中仍可显式使用自定义帧范围，并在方法说明中注明替代了校准时间段 |
| C2 | RodentFlow 计算前把分析起点 / 时长清零并按复核范围截取 | 与“校准”中的分析窗口不一致；水迷宫 / Barnes 失去“默认按试次最长时间”的规则 | 全部样本 + 校准中的分析参数交给原版 `AssayEngine`（窗口由引擎按原版规则选取）；轨迹图只画分析窗口（原版 `TrackingVisuals.windowed`） |
| C3 | RodentFlow NOR / MWM / Barnes 没有使用追踪器给出的标记位置 | 物体 A/B、平台、目标洞在默认位置，指标与实际场地不符 | 追踪时保存 `markersCM`；按原版 `makeExperimentResult` 写入 objectA/B、target；旧结果或标记在“校准”中移动后，用追踪时的场地几何重新换算标记（只读背景帧，不重新追踪），并写回结果文件 |
| C4 | RodentFlow 检测标志为 `!interpolated && confidence > 0` | 与原版（`!interpolated`）不同 | 改为原版规则（`FlowResultInputs.samples`） |
| C5 | 阶段：标定页用“视频阶段或默认阶段”，报告用“视频阶段或空字符串” | 未填写阶段时，标定与计算用的阶段不同 | 统一 `VideoRecord.effectivePhase(for:)`：空或未填写 = 任务默认阶段（标定、结果、导出、复核导出） |
| C6 | RodentLimb 事件要手动点击，结果卡片缺失 | 结果和事件来源不一致 | 结果页自动计算（该视频的标定与参数），逐帧复核中的事件同样自动计算 |
| C7 | RodentPose 分析文字的 `RPTexts.tr` 原样返回中文 | 英文界面显示中文；导出的指标名是中文 | 使用 RodentPose 原版翻译表：`tr` 跟随界面语言，导出用 `english` / `metricLabel` / `reportText`（与 iOS 相同） |
| C8 | `FlowSavedRun.startedAt` 写的是结束时间 | 记录不准确 | 记录开始时间 |

## D. 结果是否会混用（检查点）

- 结果页的计算键 = 视频 ID + 结果文件夹 + 该任务设置的指纹 + 阶段 + 是否已载入 + 语言；只显示与当前键一致的结果，切换视频或修改标定后自动重算（`TaskResultsView.key`）。
- 快速复核写入时总是写到它所属的视频（`stateVideoID`），并且只写到当前结果文件夹的复核记录；新的分析开始后旧复核不再作为“当前复核”。
- 复核记录的解码是容错的：缺字段不会让整个工作区无法读取。

## E. 仍未解决 / 未验证

- 没有在 macOS 上编译和运行；所有改动只做了语法解析和工程文件检查。
- 数值一致性：RodentPose / RodentLimb / RodentFlow 的结果尚未与 iOS 原版逐项对照。
- RodentLimb 圆筒触壁的人工改标签（iOS 可修改并保留）尚未移植，结果页只读。
- 双鼠社交（dyadic）仍只能单鼠追踪，不出结果。
- 超过 216,000 帧（30 fps 约 2 小时）的 RodentPose 结果需要在“校准”中设置较短的分析时间段（只读取该时间段前后各 30 秒）。
